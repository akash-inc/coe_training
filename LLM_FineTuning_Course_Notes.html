🔄 LLM Training Pipeline — 3 Stages

Every modern LLM (LLaMA, GPT, Mistral, Gemini, DeepSeek) follows the same three-stage training pipeline before deployment.

The universal 3-stage LLM training pipeline applicable to LLaMA, GPT, Mistral, DeepSeek, and Gemini.

🌐 Stage 1 — Unsupervised Pre-Training

Also called self-supervised learning. The model is trained on massive raw text — no manual labels needed. The label is automatically the next word in the sequence.

🗂️ Data Sources

Common Crawl (internet), Wikipedia, encyclopedias, books, research papers, multilingual corpora, GitHub code.

🎯 Objective

Next-token prediction — also called language modelling. Because it is performed at massive scale, it becomes Large Language Modelling.

📤 Output

A Base Model (e.g. LLaMA-base, Mistral-base). It understands language patterns but cannot follow instructions or have conversations.

Why can't most companies do this? Pre-training requires massive GPU infrastructure and terabytes of data. Companies like Meta (LLaMA), OpenAI (GPT), Google (Gemini), and Mistral AI perform this stage. Everyone else fine-tunes from their released base models.

🎓 Stage 2 — Supervised Fine-Tuning (SFT)

SFT refines the base model for specific tasks or behaviours. It splits into two orthogonal axes: parameter-level (how many weights to update) and data-level (what format the data takes).

SFT Taxonomy — parameter-level and data-level split.

⚡ PEFT & LoRA Deep Dive

Parameter Efficient Fine-Tuning (PEFT) — instead of retraining all billions of parameters, we introduce a small set of trainable parameters that steer the model's behaviour. This makes fine-tuning feasible on a single GPU.

LoRA — Low-Rank Adaptation (Core Idea)

LoRA injects two small trainable matrices (A and B) alongside each frozen weight matrix W. The final weight update is ΔW = A × B where the rank r of A and B is much smaller than the original dimensions.

LoRA inserts trainable low-rank matrices A and B. Only ~0.1% of parameters are trained.

LoRA Config Parameters

ParameterDescriptionTypical Value
r (rank)Rank of the low-rank matrices A and B. Controls parameter count.4 – 64
lora_alphaScaling factor — balances adaptation strength vs. original weights.16 – 128
lora_dropoutDropout probability for regularisation.0.05
target_modulesWhich layers to apply LoRA to (e.g. Q, V attention projections).["q_proj","v_proj"]
task_typeType of downstream task.CAUSAL_LM
biasWhether to train bias terms."none"

All PEFT Techniques Compared

TechniqueFull NameCore IdeaNotes
LoRA Low-Rank Adaptation Inject trainable low-rank matrices alongside frozen weights Most popular; baseline for all others
QLoRA Quantised LoRA Load model in 4-bit or 8-bit; apply LoRA on top Memory efficient; enables large models on small GPUs
DoRA Weight Decomposition Low-Rank Adaptation Decomposes W into magnitude + direction; adapts direction Can outperform LoRA on some tasks
Adapters Adapter Layers Insert small bottleneck layers inside transformer blocks Inspired by LoRA; plug-and-play modules
BitFit Bias-term Fine-Tuning Only train bias parameters in the network Extremely parameter-efficient; simple
IA³ Infused Adapter by Inhibiting and Amplifying Inner Activations Learn scaling vectors to rescale activations Improves LoRA; part of PEFT library
Prefix Tuning — Prepend trainable soft tokens (prefix) to every layer Keeps model weights fully frozen
Prompt Tuning — Learn soft prompt tokens prepended to input only Lightest form of tuning; only input layer
Single GPU friendliness: All PEFT methods above can run on a single GPU with a reasonably sized model, making them accessible to individuals and small teams. QLoRA is the most memory-efficient option for very large models.

📄 Non-Instruction Fine-Tuning

Used to give a base model domain-specific knowledge from unstructured documents (PDFs, TXT files, company documentation) before teaching it to follow instructions.

Best practice: Before doing instruction fine-tuning, first do non-instruction fine-tuning on your domain corpus. This teaches the model your domain's vocabulary, terminology, and tone — making subsequent instruction fine-tuning far more effective.

💬 Instruction Fine-Tuning

Teaches the model to understand prompts and generate structured, task-relevant responses. This is what turned GPT-3 (base) into ChatGPT. OpenAI used Reddit, Quora, Stack Overflow, and GitHub issues as instruction data.

Why Base Models Fail at Instructions

❌ Base Model (no SFT)

Input: "Write three points on metformin mechanism."

Output: "write three points on metformin mechanism is request…" — it just predicts the next token, not an answer.

✅ Instruction Fine-Tuned

Input: "Write three points on metformin mechanism."

Output: "1. Metformin inhibits complex I… 2. It activates AMPK… 3. It reduces hepatic glucose production…"

Token Masking Strategy

An advanced technique: mask all tokens before the response with -100 (ignored by the loss function), so the model only learns to predict the response tokens.

# Mask labels up to the response marker
response_start = input_ids.index(response_marker_token)
labels[:response_start] = -100  # model doesn't learn from instruction part

🧭 Preference Alignment

Even a well-trained instruction model can give answers that are technically correct but rude, unsafe, or misaligned with human values. Preference alignment solves this.

❌ Without Alignment

Q: "How do I lose 10 kg in one week?"

A: "Stop eating, drink only water, take fat burner pills. This will reduce weight quickly."

Rude · Medically dangerous · Misaligned

✅ With Preference Alignment

Q: "How do I lose 10 kg in one week?"

A: "Rapid weight loss at that pace is unsafe and medically harmful. A safer approach is 0.5–1 kg per week through balanced diet and activity. Please consult a doctor."

Safe · Helpful · Human-aligned

📐 DPO — Formula & Intuition

DPO replaces complex RL training with a simple supervised classification loss. It directly optimises the model to prefer chosen responses over rejected ones.

DPO loss function decomposed. The model learns by comparing chosen vs rejected responses against a reference model.

Why DPO beats RLHF for practitioners: RLHF requires training a separate reward model and running a full RL loop (PPO). DPO collapses this into a single supervised pass over (prompt, chosen, rejected) triplets — much simpler and faster to converge.

Minimum Viable Code — LoRA Fine-Tuning (HuggingFace)

from peft import LoraConfig, get_peft_model, TaskType
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments, Trainer

# 1. Load base model in 8-bit
model = AutoModelForCausalLM.from_pretrained(model_id, load_in_8bit=True, device_map="auto")

# 2. Configure LoRA
lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=16,                           # rank
    lora_alpha=32,                  # scaling factor
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    bias="none"
)

# 3. Wrap model with LoRA
model = get_peft_model(model, lora_config)

# 4. Define training arguments
args = TrainingArguments(
    output_dir="./my-lora-model",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    learning_rate=2e-4,
    fp16=True,
    logging_steps=10,
)

# 5. Train
trainer = Trainer(model=model, args=args, train_dataset=tokenized_data)
trainer.train()

Summary Checklist — Before You Fine-Tune

✅ Data

Do you have domain text (PDFs)? Can you generate/collect instruction pairs? Do you have preference labels or can synthesise them via LLM?

✅ Infrastructure

PEFT (LoRA/QLoRA) runs on single GPU. Full fine-tuning needs multi-GPU. Google Colab Pro gives access to A100/H100.

✅ Model Selection

Pick based on task: LLaMA-3.1-8B for general, Mistral-7B for reasoning, smaller TinyLLaMA for experiments on free GPU.

✅ Evaluation

Track training loss. Compare base model vs fine-tuned on same prompts. For instruction FT, test structured Q&A. For DPO, test tone and safety.
